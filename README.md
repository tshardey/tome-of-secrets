# Tome of Secrets

A solo TBR reading game inspired by an assortment of role playing games.

This project is built as a static website using Jekyll and is hosted on GitHub Pages. This allows the game's rules, which are written in Markdown, to be automatically converted into a navigable website.

---

## Jekyll Website Setup

The website is built from a collection of Markdown files and a few key structural folders and files. Here is a breakdown of the important parts:

* **`_config.yml`**: This is the main configuration file for the Jekyll site. It contains settings like the site's title, description, and the `baseurl` which is crucial for making sure links work correctly on GitHub Pages.

* **`_layouts/default.html`**: This is the master template for the entire site. Every page is built by injecting its content into this layout. It contains the site's overall HTML structure, including the header, the sidebar navigation, the footer, and the links to the CSS and JavaScript files.

* **`assets/`**: This folder contains all the static files for the site.
    * **`css/style.scss`**: This is the main stylesheet that controls the "Dark Academia" look and feel, including colors, fonts, and the layout of all pages.
    * **`js/anchor.js`**: This script automatically adds the "#" anchor links that appear when you hover over headers, making sections easy to share.
    * **`images/`**: This folder contains all the images used on the site, including the main hero banner and the pictures for the reward items.

* **`supabase/`**: Supabase CLI project directory. Contains `config.toml` and `migrations/` with timestamped SQL migration files for managing the cloud save database schema.

* **Markdown Pages (`.md`)**: These are the core content files for your game (e.g., `core-mechanics.md`, `rewards.md`, etc.). Each file uses "front matter" at the very top (the part between `---`) to tell Jekyll which layout to use and what the page's title is.

## Future Development & How to Update

Making changes to the website is straightforward.

### Editing Content
To edit the text on any page, simply open the corresponding `.md` file and make your changes using standard Markdown syntax. For pages with complex layouts like `rewards.md`, you will be editing HTML directly within the file.

### Adding a New Page
1.  Create a new file in the root directory (e.g., `new-section.md`).
2.  Add the required front matter to the top of the file:
    ```markdown
    ---
    layout: default
    title: Your New Page Title
    ---

    ## Your content starts here...
    ```
3.  Add a link to the new page in the sidebar navigation by editing the list in `_layouts/default.html`.

### Adding New Reward Images
1.  Make sure the image is a reasonable size (e.g., 150x150 pixels).
2.  Add the image file to the `assets/images/rewards/` folder.
3.  Open `rewards.md` and copy an existing `<div class="reward-item">...</div>` block.
4.  Update the `src` in the `<img>` tag to point to your new image file and change the text content.

### Building Game Data (JSON to JavaScript)
This project uses JSON files as the source of truth for game data (XP levels, bonuses, items, etc.). These JSON files are automatically converted to JavaScript exports by a build script.

**When to run the build:**
- After cloning the repository for the first time (done automatically when the Docker containers start)
- After editing JSON files in `assets/data/`
- After adding new JSON data files

**To generate the JavaScript exports:**
```bash
node scripts/generate-data.js
```

This generates `assets/js/character-sheet/data.json-exports.js` which is required for the character sheet to function. This file is automatically generated and should not be edited manually.

### Local Development (Optional)
To see your changes live on your own computer before pushing them to GitHub, this project ships a **Docker Compose** development environment (`docker-compose.yml` + `docker/Dockerfile`). It provides Ruby 3.3 / Jekyll, Node.js LTS, the GitHub CLI, the Supabase CLI, Google Chrome (plus a `chrome-for-agents` shim) and the Claude Code CLI, so you don't need to install any of them on your machine.

#### Prerequisites

1.  **Docker Desktop** (or Docker Engine with the Compose plugin): Download and install from docker.com/products/docker-desktop. Make sure it is running before you proceed.
2.  **Supabase config:** Copy `_config.supabase.yml.example` to `_config.supabase.yml` (git-ignored) and fill in the values. The `jekyll` service passes this file to Jekyll and will not start without it; the site's art is hosted in Supabase Storage, so the real values are needed for images and cloud sync.

#### Running the Development Environment

All commands run from the repository root on your host:

```bash
docker compose build                    # first time, or after docker/ changes
docker compose up jekyll                # serve the site (add -d to run in the background)
docker compose run --rm dev             # interactive shell inside the container
docker compose run --rm dev npm test    # run the Jest suite (starts in tests/)
docker compose down                     # stop the containers (gems/node_modules volumes are kept)
```

1.  **Start the Server:** `docker compose up jekyll` runs `bundle exec jekyll serve --config _config.yml,_config.supabase.yml` with polling enabled, so edits made on the host (including Windows) trigger a rebuild. The first start installs the gems and test dependencies and generates `data.json-exports.js`; later starts are fast.
2.  **View Your Site:** Open **`http://localhost:4000/tome-of-secrets/`** in your browser. LiveReload is enabled, and any change you save triggers a rebuild — refresh to see it.

Gems and `tests/node_modules` live in Docker named volumes, so they never land in your working tree or clash with a host `node_modules`. The `dev` container's home directory is a volume too, so `gh auth login` / `supabase login` survive between `docker compose run --rm dev` sessions. `docker compose down -v` deletes these volumes if you want a clean reinstall.

**Claude Code in the container:** the `dev` service mounts your host `~/.claude` (as the old devcontainer did). Host-only settings such as hook commands pointing at Windows executables will not run inside Linux; set `TOS_CLAUDE_DIR` to a separate folder to give the container its own Claude Code config.

**Serving another checkout or worktree:** set `TOS_SRC` to its path and give it its own project name so its volumes stay separate (stop any other server on port 4000 first):

```bash
TOS_SRC=../other-worktree docker compose -p tos-other up jekyll                # bash
$env:TOS_SRC='../other-worktree'; docker compose -p tos-other up jekyll        # PowerShell
```

#### Editing JSON data locally
If you change any files under `assets/data/`, regenerate the JS exports before refreshing the site:
```bash
docker compose run --rm dev node ../scripts/generate-data.js
```
This keeps `assets/js/character-sheet/data.json-exports.js` in sync for the character sheet and tables. (The containers also regenerate it on every start, but a running `jekyll` service does not, so run this or restart `jekyll` after editing JSON.)

## Testing

This project uses [Jest](https://jestjs.io/) for JavaScript testing to ensure the interactive functionality of the Character Sheet remains stable.

The Docker development image already includes Node.js and npm, and the container installs the test dependencies (`npm ci` in `tests/`) automatically whenever `tests/package-lock.json` changes, so no additional installation is required on your local machine.

### Running the Test Suite

From the repository root:

```bash
docker compose run --rm dev npm test
```

Or open a shell with `docker compose run --rm dev` (it starts in `tests/`) and run `npm test`, `npm run validate-data`, or `npm run test:e2e` (Playwright, using the bundled Chrome) from there.

## Supabase Database Migrations

The cloud save feature uses [Supabase](https://supabase.com/) as a managed Postgres backend. Database schema changes are managed via the Supabase CLI, which is pre-installed in the Docker development image (open a shell with `docker compose run --rm dev`).

### First-Time Setup

1.  **Authenticate** with your Supabase account:
    ```bash
    supabase login
    ```
2.  **Link** to the remote project:
    ```bash
    supabase link --project-ref cdhorluhpuchzlnahzlt
    ```

### Creating and Applying Migrations

1.  **Create** a new migration:
    ```bash
    supabase migration new <descriptive-name>
    ```
    This creates a timestamped SQL file in `supabase/migrations/`.

2.  **Write your DDL** in the generated file. Keep migrations idempotent (`IF NOT EXISTS`, `OR REPLACE`).

3.  **Apply** pending migrations to the remote database:
    ```bash
    supabase db push
    ```

See [`project-docs/SUPABASE-CLOUD-SAVE.md`](project-docs/SUPABASE-CLOUD-SAVE.md) for full Supabase setup details including auth configuration and RLS policies.
